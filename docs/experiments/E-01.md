# E-01 라이다 끊김 (예비 확인, safety_gate 없음)

- 일시: 2026-11-22
- 환경: MentorPi A1, Raspberry Pi 5, Docker MentorPi(ros:humble), 바퀴 정지 상태
- 방법: health_monitor 실행 중 `lidar.launch.py`를 Ctrl+C로 종료한 뒤 다시 실행
- 설정: timeout_sec 2.0, min_hz 9.0, rate_window_sec 1.0, recovery_hold_sec 2.0, 판정 10 Hz
- 관련 요구사항: SR-01(끊김 2.0 s → FAULT), SR-03(주기 저하 → DEGRADED), SR-06(회복 2.0 s 유지)

시각은 모두 ROS 로그와 `/robot_status`에 찍힌 Unix 시간(1970-01-01 UTC부터의 초)이다.
라이다, health_monitor, `/robot_status`는 같은 컴퓨터의 같은 시계를 쓰므로 값을 그대로 빼서 시간 차이를 구한다.

## 1. 감지 시간 (3회)

"라이다 종료 시각"은 라이다 창에서 Ctrl+C를 누른 순간이며, 라이다 로그의
`signal_handler(signum=2)` 줄의 시각을 사용했다.

| 1 | 1795341255.981 | +0.85 s | +1.95 s |

| 3 | 1795341850.821 | +0.86 s | +1.96 s |

### 마지막 스캔 기준 (2회차)

Ctrl+C를 누르기 직전의 마지막 스캔 시각은 로그에 없다. 대신 `/robot_status`의
`value`(마지막 스캔 후 지난 시간)를 메시지 시각에서 빼서 구했다.

- 마지막 스캔: 1795341832.882 (stamp) − 5.664 (value) = 1795341827.218
- 감지 시간(M-01): 1795341829.282 (FAULT) − 1795341827.218 = **2.06 s**
- 기대 범위: timeout 2.0 s + 판정 주기 최대 0.1 s = 2.0~2.1 s → **일치**

## 4. 관찰

1. **단계적 악화**: 라이다가 멈추면 약 0.86 s 뒤 1 s 윈도우 안의 스캔이 2개 미만이 되어 rate 0 → DEGRADED,
   약 1.97 s 뒤 timeout → FAULT. 감속 후 정지 순서가 됨. 7단계 safety_gate에서 이 순서를 그대로 쓸지 결정
2. **늦은 구독 재시도 동작**: 1회차 시작 시점에 `/scan_raw`가 discovery 전이라 보이지 않았고,
   1 s 뒤 재시도에서 구독됨 (SR-10 유예 5 s 안)
3. **정상 상태 U1003 오탐 1회** (별도 실행): 시작 17 s 뒤 약 0.9 s 동안 DEGRADED, 2 s hold 후 OK.
   ```
   [WARN] [1795340921.021001730] level -> DEGRADED: U1003 rate below minimum (/scan_raw)
   [INFO] [1795340923.920932941] level -> OK
   ```
   → 원인은 주기 흔들림이 아니라 스캔 1개 누락(523.9 s에 15회). rate_window_sec 2.0으로 조정 후 오탐 0회 ([RATE-01](RATE-01.md))
4. **재수신 직후 U1003 1회**: 첫 스캔 하나로는 rate를 계산할 수 없어 0 Hz로 판정됨.
   최종 등급은 FAULT 유지라 안전 영향 없음. 회복 대기가 0.1 s 늦어짐 → 개선 후보
5. **서드파티 라이다 드라이버 비정상 종료**: 2·3회차에 Ctrl+C 시 `ldlidar_stl_ros2`가
   `buffer overflow detected`로 exit −6. 1회차는 정상 종료. 종료 방식과 관계없이 감지 시간은 같았음
   (메시지 도착만으로 판단하기 때문). 벤더 코드는 수정하지 않음

## 5. 결론

- SR-01: 라이다 끊김 후 2.06 s(마지막 스캔 기준)에 U1002 FAULT → **충족**
- SR-06: 재수신 후 2.0 s 연속 정상에서 OK 복귀 → **충족**
- SR-03: 정상 상태 오탐 1회 → 원인 확인 후 rate_window_sec 2.0으로 조정, **오탐 0회 확인** ([RATE-01](RATE-01.md))
- 남은 확인: safety_gate 연결 후 모터 입력 0 속도까지의 시간 (9단계 E-01 본 실험)
