# E-02 RRC 노드 종료 (모터 연결, 주행 중)

- 일시: 2026-11-23
- 환경: MentorPi A1, Raspberry Pi 5, Docker MentorPi(ros:humble), **바퀴를 띄운 상태**
- 실행: `supervisor_bringup` 전체, `/cmd_vel`에 0.1 m/s를 10 Hz로 계속 발행 (바퀴 회전 중)
- 방법: `ros_robot_controller` 프로세스 하나만 `kill -INT <PID>`로 종료
  (Ctrl+C가 노드에 전달되지 않아 같은 신호인 SIGINT를 PID로 직접 보냄)
  (`pgrep -af ros_robot_controller`는 imu_calib와 rosbag까지 함께 찾아서, PID를 지정해 하나만 종료)
- 데이터: rosbag `experiments_raw/E-02_20261123_122916/bag` (git 제외), bringup 로그
- 관련: SR-02, SR-09 / 잔여 위험 RR-04

## 1. 왜 하는가

명령은 `safety_gate → odom_publisher → ros_robot_controller → USB 시리얼 → RRC Lite 보드 → 모터`로 간다.
`ros_robot_controller`가 죽으면 gate의 정지 명령도 보드에 도착하지 않는다.
이때 (1) 감시가 이 상황을 알아채는지, (2) 모터가 어떻게 되는지를 확인한다.

## 3. 관찰

1. **감지는 기대대로 (SR-02)**: IMU는 `ros_robot_controller`가 보드에서 받아 발행하므로, IMU가 끊긴 것으로 RRC 통신 단절을 2.01 s에 감지했다.
2. **모터는 gate보다 먼저 멈춤**: 정지 명령이 보드에 전달될 수 없는 상황인데도 바퀴가 바로 멈췄다.
   `ros_robot_controller`가 종료하면서 정지시켰거나, 보드 펌웨어가 시리얼이 닫히자 스스로 멈춘 것으로 보인다.
   이번 시험은 정상 종료 신호(SIGINT)라 두 경우를 구분할 수 없다.
3. **`/odom_raw`는 노드가 죽은 뒤에도 계속 나옴**: `ros_robot_controller` 종료 후 녹화 끝(+131.81 s)까지 약 29 s 동안 계속 발행됐다.
   `/odom_raw`는 모터 보드와의 통신 상태를 나타내지 않는다. RRC 통신 감시는 IMU가 맞는 신호이며, 실제로 IMU가 이 고장을 잡았다.

## 4. 결론

- SR-02: RRC 통신 단절을 IMU 끊김으로 2.01 s에 감지 → **충족**
- 모터 경로가 끊겼을 때 모터 상태: **정상 종료(SIGINT)에서는 즉시 정지**.
  크래시(SIGKILL)에서는 바퀴가 계속 회전했다 ([E-CRASH](E-CRASH.md) E-02b).
  즉 이번 즉시 정지는 노드가 종료하면서 보드에 보낸 정지 명령 때문이었고, 펌웨어 자체에는 명령 timeout이 없다 (RR-04)
- 감시 대상 선택 근거: `/odom_raw`는 보드 단절 후에도 계속 나오므로 RRC 상태 판단에 쓸 수 없음. IMU 감시가 필수
