## 4. 관찰

1. **쓰지 않는 채널 처리 확인**: `/safety_gate/controller/cmd_vel`은 명령이 한 번도 없었는데 STOP 구간에서만 0을 냈고(762개 ≈ STOP 총 76 s × 10 Hz), PASS 구간에서는 아무것도 내지 않았다.
   쓰지 않는 채널에 0을 계속 보내 쓰는 채널의 명령을 덮어쓰지 않는다는 설계와 일치한다.
2. **두 가지 STOP 경로**: ②는 health_monitor가 고장을 알린 경우로 SLOW를 거쳐 STOP, ⑤는 health_monitor 자체가 사라진 경우로 SLOW 없이 바로 STOP.
3. **정상 라이다에서 감속 3회 (U1003 오탐)**: 약 2분 동안 3회, 매번 약 2.9 s.
   주기는 10.000 Hz로 안정적이나 약 35 s마다 스캔 1개가 누락됨. 1 s 윈도우에서 1개 누락 시 8.89 Hz.
   → 원인은 스캔 1개 누락(523.9 s에 15회). rate_window_sec 2.0으로 조정 후 오탐 0회 ([RATE-01](RATE-01.md))
4. **⑥ 종료 로그 누락**: gate의 `shutdown: sent zero velocity` 로그가 파일에 없다. Ctrl+C가 `tee`도 함께 종료시켰기 때문.
   bag에는 0 송신이 기록되어 있어 동작은 확인됨. `run_logged.sh`를 `tee -i`로 수정함.
5. **⑤ 지연 미측정**: `/robot_status`가 녹화되지 않아(녹화 창에서 `robot_interfaces` 타입을 몰랐음) health_monitor가 멈춘 시각을 알 수 없다.
   `record_experiment.sh`가 작업공간을 직접 불러오도록 수정함(RATE-01에서 `/robot_status` 녹화 확인). 9단계 E-05에서 측정.

## 5. 결론

- SR-04, SR-06, SR-09, SR-13, 정상 종료 시 0 송신: **동작 확인**
- SR-05(두 입력 모두 gate 경유)는 8단계 bringup remap 후 모터 연결 상태에서 확인
- U1003 오탐은 health_monitor 기준 문제로 분리해 [RATE-01](RATE-01.md)에서 해결
